工具很多，真正每天会打开的却不多。比起收集越来越长的清单，我更喜欢问一个简单的问题：它让今天的某一件事变容易了吗？

这是一篇示例笔记，也是一份可以继续补充的小清单。

## 从一个具体的问题开始

找不到以前收藏的文章，就先整理书签。经常忘记运行项目的命令，就把命令写进说明文档。

问题足够具体，工具是否合适也会更容易判断。

## 让常用入口近一点

这个小站把常逛的资源放在[收藏夹](/library/?category=bookmarks)里。以后不用为了找一个入口，再翻很多层书签。

也给文章搜索加了一个快捷键：

**按 `⌘ K`，或 Windows / Linux 上的 `Ctrl K`，可以打开站内搜索。**

### 一份短一点的命令清单

```sh
# 本地写作与预览
npm run dev

# 检查类型并生成网站
npm run build

# 查看构建后的页面
npm run preview
```

有时，让人省心的并不是一个全新的工具，而是把已经在用的东西整理好。

## 少一点打断

我喜欢能安静待在一旁的工具：需要时能够找到，用完后也不会一直提醒我它的存在。

对博客也是一样。动效可以有，但阅读时应该让位给文字。按钮应该告诉人会发生什么，链接也应该通向明确的地方。

## 给自己的工具箱留点空间

工具箱不必填满。留一点空位，才能在遇到新问题时，认真考虑自己究竟需要什么。
